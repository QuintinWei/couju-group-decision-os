## 作品简介

凑局是一款 AI 群体决策产品。它不是再给一个人生成一份推荐清单，而是帮助 2–6 个人在预算、时间、距离、忌口和兴趣不同的情况下，快速找到一个“所有硬约束都满足、没有人明显被牺牲”的共同方案。

核心闭环：

```text
创建房间 → 分享链接 → 目标成员全部加入 → 提交空闲时间与个人通勤上限
→ 生成多人可达交集卡池 → 独立滑卡 → AI 理解补充偏好
→ 共同底线过滤 → Pareto + Nash 公平排序 → 锁定行动卡
```

推荐演示路径：

1. 点击「体验完整决策」。
2. 选择「一起聚餐」或「周末活动」。
3. 选择城市、日期范围、上午 / 下午 / 晚上和预计时长；可输入地铁站，也可授权浏览器定位。
4. 默认使用「给我灵感」跨类型发现，由系统先建立较大的城市候选池。
5. 复制房间链接，用另一个浏览器或设备以朋友身份加入。
6. 目标人数全部加入后，每位成员以“日期 + 开始/结束范围”提交空闲时间，系统求出共同时间。
7. 每个人在选卡前提交预算、30 / 60 / 90 分钟或不限的单程通勤上限，以及场景偏好。
8. 系统最多召回 5 批候选；只有同时满足每位成员各自通勤上限的地点，才能组成首轮 12 张共享卡。交集不足时会明确提示调整边界，不用房主卡池顶替。
9. 全员对同一批卡独立选择喜欢 / 还行 / 不喜欢；还可用自然语言补充忌口、到达时间、排队偏好等信息。
10. 全员完成后启动公平排序，查看唯一的「群体最优解」及每位成员满意度、Nash 福利、通勤与预算解释。
11. 锁定方案，体验地图、日历与房间分享。

### 共享候选轮次

- 每轮固定展示 12 张共享卡；所有已加入成员都对同一批卡片提交「喜欢 / 一般 / 不喜欢」，私人卡不会直接成为最终结果。
- 如果某位成员把本轮 12 张全部标记为「不喜欢」，只为该成员生成 3 张私人救援卡。私人卡最多选择 1 张提名，或跳过；被拒绝的私人卡不会混入后续共享池。
- 下一轮仍然固定 12 张：保留有效提名和基于全体反馈学习出的候选，同时至少保留 4 张新的探索卡。私人提名也必须经过全体成员再次评价，才能进入最终公平排序。
- 最多进行 3 轮。必须达到建房时设定的目标人数，且全员提交本轮反馈后，创建者才能推进下一轮；成员可以请求刷新，但不能绕过其他成员。
- 反馈学习使用可解释的固定权重：喜欢 `+2`、一般 `+0.5`、不喜欢 `-1.5`。权重只影响下一轮候选构成，不替代硬约束，也不把个人偏好直接变成群体结论。
- 第 3 轮仍无可行解时，系统展示冲突来源和可调整的约束，不伪造一个“最优地点”。

## 为什么这是 AI 产品，而不只是投票工具

投票工具只能统计“谁选了什么”，凑局还要先理解每个人为什么喜欢或拒绝，再把自然语言、滑卡反馈、时间、预算和通勤边界映射到同一套候选特征中。DeepSeek 负责理解补充要求和生成可读解释，确定性算法负责验证地点是否可行并完成多人公平排序；AI 不虚构地点，也不能绕过任何成员的硬约束。

| 模块 | 方法 | 作用 |
|---|---|---|
| Preference Extractor | DeepSeek JSON Output + 校验 | 把“海鲜过敏、别太吵、最好不用排队”抽取为过敏底线及安静、少排队偏好 |
| Candidate Retriever | 探索 / 倾向 / 学习三种召回策略 | 高德按娱乐或菜系关键词分桶、多批召回，再按所有成员各自通勤上限求共同可达交集 |
| Room Coordinator | D1 持久化房间 | 保存真实成员、独立提交与候选快照，让分享链接跨设备可用 |
| Feasibility Checker | 确定性规则 | 任一成员明确拒绝或触发预算、时间、忌口底线时排除候选；通勤按容差重罚 |
| FairMix Engine | Pareto + Nash + 最低满意度 | 先保护最不满意成员，再最大化群体乘积福利 |
| Evidence Writer | DeepSeek + 确定性回退 | 只解释算法已经产生的名次，无权改写名次或补造地点事实 |
| Action Connector | 地图 / 日历深链 | 把推荐变成现实行动 |

详细 Prompt、输入 / 输出和降级策略见 [AI 工作流说明](docs/AI_WORKFLOW.md)。

## AI 工作流示例

用户输入：

```text
我海鲜过敏，想找安静一点、适合聊天的地方，最好不用排队。
```

结构化输出：

```json
{
  "hard_constraints": [
    { "type": "allergy", "value": "海鲜", "confidence": 0.99 }
  ],
  "soft_preferences": [
    { "feature": "quiet", "direction": "maximize", "weight": 0.8, "confidence": 0.93 },
    { "feature": "conversation", "direction": "maximize", "weight": 0.8, "confidence": 0.91 },
    { "feature": "queue_time", "direction": "minimize", "weight": 0.7, "confidence": 0.82 }
  ],
  "needs_confirmation": true
}
```

用户确认标签后，硬约束进入候选过滤，软偏好进入个人效用计算；模型无权自行把软偏好升级为硬约束。

## FairMix 公平共识

普通投票容易让多数人的最爱变成少数人的雷区。凑局先淘汰违反任意成员硬约束的候选，再综合：

```text
若存在最低满意度 ≥ 60 的候选：
Score = 0.35 × 最低个人效用 + 0.55 × Nash 几何均值 + 0.10 × 平均效用

否则：
Score = 0.65 × 最低个人效用 + 0.25 × Nash 几何均值 + 0.10 × 平均效用

最后扣除 0.35 × 数据不确定性，并优先保留 Pareto 前沿候选。
```

首轮共享卡池会先执行多人通勤交集：对每个候选分别计算所有成员的通勤估算，任意成员超过自己的上限，该地点就不能进入共享 12 张。当前通勤仍是基于坐标的估算而不是实时路网时间，因此界面明确使用“估算”表述；最终排序还会再次执行预算、时间、忌口、明确拒绝等硬约束，并综合最低满意度与 Nash 福利。

`Group Fit` 只用于同一会话内排序，不包装成“成功概率”。

## 隐私与可信度

- 房间通过随机房间号和设备成员令牌工作，不要求注册。
- 房间号从完整的 36 进制字母表取样；仅凭房间号只能看到城市、时间和已加入人数，看不到任何成员昵称。
- 成员令牌只保存在各自设备，服务端仅保存哈希；出发地只要求地铁站或商圈，不要求精确住址。
- 系统定位只在用户点击并授权后调用；坐标会用于候选通勤估算，识别到支持城市时自动同步城市。
- 消耗服务端 DeepSeek 额度的接口需要有效成员身份；结果解释只收到预算与通勤标签，成员昵称和出发地不会离开服务端。
- 过敏、无障碍、明确时间等硬约束不会被平均分抵消。
- 无可行候选时不伪造答案，而是明确进入“调整底线”状态。
- 房间数据保留 30 天，之后连同成员记录一并清理。
- Prompt 和 Schema 需要版本化；算法结果可回放、可测试。

## 数据模式与实现边界

为了保证作品展示无需 API Key、网络波动时仍可完整体验，系统有两层明确模式：

- 配置 `DEEPSEEK_API_KEY`：服务端默认直连 DeepSeek 官方并调用 `deepseek-v4-flash`，返回 JSON 字段后经代码白名单校验；失败时使用本地规则抽取。
- 配置 `AMAP_WEB_SERVICE_KEY`：十城通过高德地点搜索 2.0 获取 POI，并保留 POI ID、地址、坐标与返回时间；失败时使用明确标注的演示候选。
- DeepSeek 负责字段理解和结果解释；FairMix 始终由确定性函数执行，不由语言模型决定名次。
- 高德地理编码把手输地铁站 / 商圈转换为坐标；浏览器定位会经坐标转换与逆地理编码，并在识别到十城时自动更新城市。首轮从最多 5 批候选中去重并求全员可达交集；后续轮次保留反馈学习、历史排除、同品牌去重和探索配额。
- 本阶段未接入美团 / 大众点评 API；高德评分只是候选质量信号之一，不是最终群体排序依据。
- 高德返回的是地点事实，不等同于实时可订、实时营业或实时价格；价格、营业状态、可预约性和真实路线时间仍需用户在行动前确认。无 Key 或接口失败时，Demo 仍可运行，但候选会明确处于演示数据模式。

## 本地运行

要求 Node.js `>= 22.13.0`。

```bash
npm install
npm run dev
```

可选服务端配置见 `.env.example`：

```text
DEEPSEEK_API_KEY=
DEEPSEEK_API_BASE=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TIMEOUT_MS=45000
AMAP_WEB_SERVICE_KEY=
```

构建与验证：

```bash
npm run build
npm test
```

## 项目状态

当前版本已经是可跨设备体验的真实多人 MVP：目标成员全部加入后提交时间与个人边界，系统生成多人共同可达的首轮共享卡池；全员独立反馈后由 FairMix 产生唯一结果，并支持私人发现、最多三轮换批、否决重排、地图与日历动作。当前尚未接入高德实时公交 / 驾车路线矩阵及商户订座能力，通勤明确按坐标估算。
